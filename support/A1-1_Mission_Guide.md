## 2. 산출물 ① 동작하는 프롬프트 관리 프로그램

> 📌 **근거: 미션 `2-1. 동작하는 프롬프트 관리 프로그램`, `4. 기능 요구 사항 3~10항`**

### 2-1. 반드시 구현해야 하는 7개 기능

| 메뉴 | 기능 | 놓치기 쉬운 조건 |
|:--:|---|---|
| 1 | 프롬프트 추가 | 입력값이 비면 **다시 입력 요청**, 즐겨찾기 기본값 `False` |
| 2 | 프롬프트 목록 | **별도 브랜치에서 작업**해야 함 (4-6항) |
| 3 | 카테고리별 조회 | 결과 없을 때 안내 메시지 |
| 4 | 프롬프트 검색 | **제목 또는 내용** 둘 다 검색 대상 |
| 5 | 상세 보기 | 잘못된 번호 입력 시 안내 메시지 |
| 6 | 즐겨찾기 관리 | 추가/해제 **토글** 방식 |
| 7 | 즐겨찾기 목록 | 즐겨찾기만 모아서 출력 |
| 0 | 종료 | 프로그램 정상 종료 |

공통 조건으로 **각 기능 수행 후에는 반드시 메뉴로 돌아와야** 하며, **잘못된 번호를 입력하면 안내 메시지를 출력하고 메뉴를 다시 보여주어야** 합니다. (근거: `4-3. 프로그램 실행 및 메뉴`)

### 2-2. 데이터 구조 예시

> 📌 **근거: 미션 `4-4. 기본 프롬프트 데이터`** — "리스트와 딕셔너리를 사용", "제목, 내용, 카테고리, 즐겨찾기 여부를 포함"

```python
prompts = [
    {
        "title": "블로그 글 작성 도우미",
        "content": "당신은 10년 경력의 전문 블로거입니다...",
        "category": "텍스트 생성",
        "favorite": True
    },
    {
        "title": "제품 썸네일 생성",
        "content": "다음 제품의 매력적인 썸네일 이미지를 생성해주세요...",
        "category": "이미지 생성",
        "favorite": False
    },
    {
        "title": "IT 컨설턴트 페르소나",
        "content": "당신은 15년 경력의 IT 컨설턴트입니다...",
        "category": "페르소나",
        "favorite": False
    },
]
```

**카테고리 예시**: 텍스트 생성 / 이미지 생성 / 영상 생성 / 페르소나 / 자동화 / 기타

여기서 중요한 포인트가 하나 있습니다. 이 3개는 아무 내용이나 채워 넣으면 안 되고, **이전 미션(GenAI 기초·이미지 생성·자동화 등)에서 실제로 작성했던 프롬프트**여야 합니다.
(근거: `7. 제약 사항 – Git / GitHub` 마지막 항목)

### 2-3. 자주 하는 착각 ⚠️

> 📌 **근거: 미션 `2-1`** — "프로그램 실행 중에 추가한 프롬프트와 즐겨찾기 상태가 유지된다 **(종료 시 초기화)**"

파일로 저장(영속화)하는 기능은 **필수가 아니라 보너스 1번**입니다.
필수 범위에서는 `prompts` 리스트를 메모리에 두고 실행 중에만 유지되면 충분합니다.
욕심내서 JSON 저장부터 만들다가 정작 브랜치·커밋 요건을 놓치는 경우가 많으니, 순서를 지키시는 편이 안전합니다.

## 4. 산출물 ② GitHub 저장소 — 사실상 이 미션의 진짜 핵심

> 📌 **근거: 미션 `2-2. GitHub 저장소`, `4-2. Git 저장소 설정 및 초기화`, `7. 제약 사항 – Git / GitHub`**

### 4-1. 8개 명령어를 각각 1회 이상 "실제로" 사용

`init` · `add` · `commit` · `push` · `pull` · `checkout` · `clone` · `merge`

이 중 **`pull`과 `clone`은 혼자 개발하면 쓸 일이 없어서** 가장 많이 빠뜨리는 항목입니다. 의도적으로 상황을 만들어 주셔야 합니다.

| 명령어 | 자연스럽게 만드는 방법 |
|---|---|
| `clone` | 공개 샘플 저장소 1개를 내려받아 폴더 구조·로그 확인 후 삭제 (`4-2`항에 명시) |
| `pull` | GitHub 웹에서 README.md를 한 줄 수정 → 로컬에서 `git pull` |
| `checkout` / `merge` | "프롬프트 목록" 기능을 `feature/list` 브랜치에서 작업 후 main에 병합 |

### 4-2. 의미 있는 커밋 10개 이상 — 예시 시나리오

기능 단위로 쪼개면 자연스럽게 10개가 넘습니다.

```text
1.  chore: 프로젝트 초기 설정 및 .gitignore 추가
2.  docs: README 프로젝트 제목 작성
3.  feat: 기본 프롬프트 데이터 3건 등록
4.  feat: 메뉴 출력 및 번호 선택 기능 구현
5.  feat: 잘못된 입력 처리 및 안내 메시지 추가
6.  feat: 프롬프트 추가 기능 구현
7.  feat: 프롬프트 목록 조회 기능 구현   ← feature/list 브랜치
8.  feat: 카테고리별 조회 기능 구현
9.  feat: 키워드 검색 기능 구현
10. feat: 프롬프트 상세 보기 기능 구현
11. feat: 즐겨찾기 추가/해제 및 목록 기능 구현
12. refactor: 기능별 함수 분리
13. docs: README 실행 방법 및 기능 목록 작성
```

`update`, `수정`, `ㅁㄴㅇㄹ` 같은 메시지는 "의미 있는 커밋"으로 인정받기 어렵습니다.
**무엇을 왜 바꿨는지**가 드러나야 합니다.

### 4-3. 브랜치 작업 위치가 지정되어 있음

> 📌 **근거: 미션 `4-6. 프롬프트 목록 (브랜치 활용)`** — "main 브랜치 이외의 추가 브랜치를 생성하고 **이 기능을 해당 브랜치에서** 작업한다"

```bash
git checkout -b feature/list
# ... 목록 기능 구현 ...
git add .
git commit -m "feat: 프롬프트 목록 조회 기능 구현"
git checkout main
git merge --no-ff feature/list
```

`--no-ff` 옵션을 권해 드립니다. 그래야 `git log --graph`에서 **가지가 갈라졌다 합쳐지는 모양**이 눈에 보이고, 제출용 스크린샷에서 병합 이력이 명확히 증명됩니다.

### 4-4. README.md 필수 4개 항목

> 📌 **근거: 미션 `4-12. README.md 작성`**

1. 프로그램 이름과 간단한 설명
2. 실행 방법
3. 기능 목록
4. 등록된 프롬프트 카테고리 설명

네 가지가 **모두** 들어가야 합니다.

## 6. 권장 진행 순서

1. **환경 세팅** (`4-1`항) → 개발 환경 스크린샷 촬영
2. **저장소 생성 + `init` + 첫 `push` + `.gitignore` + README 제목** (`4-2`항)
3. **샘플 저장소 `clone`** 후 로그 확인 → `clone` 요건 소진
4. **기본 데이터 3건 + 메뉴 골격** 구현
5. **기능을 하나씩 구현하며 매번 커밋** ← 커밋 수는 여기서 확보됩니다
6. **목록 기능만 별도 브랜치**에서 작업 후 병합
7. GitHub 웹에서 README 수정 → 로컬 `pull` → `pull` 요건 소진
8. **함수 분리 리팩터링 + README 완성**
9. 실행 / 로그 스크린샷 촬영 후 제출

`.gitignore`에는 `__pycache__/`, `.venv/`, `.DS_Store` 정도를 넣어 두시면 충분합니다.
